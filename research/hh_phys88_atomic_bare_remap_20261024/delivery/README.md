# PHYS88 mechanical delivery

The helper reads, packages and restores existing bytes. It does not import scientific modules, run a symbolic reference or numerical child, acquire a gate/lease, mutate Git, upload, download or issue scientific admission. Root owns expected-SHA publication, PR state and the approved Drive Browser workflow. Dropbox dispatch requires explicit stage authorization.

## S0 readiness and freeze procedure

Preparation is not permission to freeze an incomplete stage. Wait until root's current R6/Wolfram files and exact S0 scope manifest are ready and published. Root supplies the actual containing commit/tree and verifies its PR/native binding. The owned-file set comes from that immutable commit; untracked implementation work and figure caches are not included. Root excludes cache paths from the publication itself rather than silently dropping a published file from delivery identity checks.

Once root authorizes the stage:

1. Snapshot only the explicitly requested post-commit publication/failure receipts privately; do not call them published Git blobs. Do not change private intake while a freeze is being adopted or packed.
2. Run `freeze` to a fresh file outside private intake. Return its exact SHA and counts for root adoption.
3. Use **`pack-atomic`** with the root-adopted freeze SHA, a new staging directory and the final unique upload basename. The command waits for a complete closed pack, checks its whole size/SHA and every CRC, makes a closed verified same-directory temporary copy, atomically places it without replacing an existing file, then reopens and verifies the exact final pathname. The staging source and any failed output remain intact.
4. Immediately before each provider dispatch, run `verify-upload` against the exact pathname that provider will read. A previous check on another pathname or an earlier upload is not a current source-byte check. Recheck a copied/renamed repair file before using it.
5. Record actual Dropbox completion and root's actual Drive UI acknowledgement separately from exact-ID metadata. Stage S0/S1/S2 evidence is ACK/metadata; it does not claim actual whole remote GET or restoration.

`pack` remains available as a low-level create-only operation, but the prescribed stage and FINAL placement procedure is `pack-atomic`. No automatic retry is performed. A mismatch retains the failed bytes/receipt and returns to root for a concrete repair decision. The earlier PHYS87 shortened packaging source had an unresolved cause; atomic placement is a targeted delivery procedure, not a claim that its cause was proved.

## FINAL actual restoration

After the FINAL containing commit and adopted freeze, package with the same closed atomic procedure. Each provider must return its own actual complete downloaded ZIP. The downloader must finish with a completed receipt **before restore starts**. Use fresh paths; no HEAD, Range, preflight or automatic retry is needed.

`restore` checks the whole archive SHA, all member CRCs, every payload SHA256, every repository native Git blob/mode, actual extraction and extracted-file rehash. It checks the whole parent ZIP once and performs zero nested historical restorations.

The separate authoritative remote check uses exact remote commit → root tree → research tree → complete owned subtree with `truncated=false`. Require exact path/type/mode/set equality, and independently hash every actual downloaded repository payload and extracted file as a Git blob against those remote tree IDs. Report **remote tree IDs versus restored-byte blob identities N/N**. Named key files actually read from remote are a separate raw-read count; N/N identities do not mean N raw Git downloads. The local restore helper alone does not fetch the authoritative remote mapping.

External main JSON is assembled from actual provider receipts, root claims, counters and original saved-output identities. Its own future hash/IDs/ACKs/readbacks stay outside itself. A finite terminal record may bind actual main-JSON dual raw readbacks; terminal acknowledgements belong in the final PR body rather than an unbounded JSON chain. Scientific scope, remaining physical gates, unknown costs and no-reset accounting remain explicit.

```bash
python delivery88.py freeze --repo REPO --head FULL_PUBLISHED_STAGE_SHA --stage S0 --private-root PRIVATE_INTAKE --dependencies-root PARENT_DIRECTORY --output FRESH_INPUT_FREEZE.json --receipt FRESH_FREEZE_RECEIPT.json

```
