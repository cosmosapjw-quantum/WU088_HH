# PHYS70 독립 성능 근거 검토

검토 시각: 2026-10-20T03:12:34.827201+00:00

**판정: 같은 샌드박스의 원래 L28 문제에서 정확도 조건을 만족하는 성능 개선 근거를 확인했다.** 이 검토는 이미 완료된 18개 적분과 마이크로벤치마크를 읽었다. 새 적분·콜백·단계 실행은 각각 0회이고 생산 코드는 수정하지 않았다.

세 엔진은 같은 실행 파일 `303efb12fb6c6169b97440a1224d30730e5194a6230c02d469a13a25b9270c13`과 같은 seed·원본 NPZ를 사용했다. 원본 B27, k=7/10, E=49/200 Hartree, T65, L28, m=0, target(21,20), 96점 각도 규칙을 유지했고 HH_R10은 OFF다. PHYS63의 질적 존재는 ESTABLISHED_REUSED 상태다.

영수증의 54개 파일 해시, 18개 요청과 결과의 연결, 14개 현재 소스 pin, 실제 실행 파일·seed·NPZ·기존 인증서의 해시를 대조했다. 18개 모두 반환 코드 0, 완료 상태, tau 0→38, 유한한 실수 상태 234개×2를 갖고 거절 단계는 0개다.

정확한 Fraction과 정수 제곱근으로 기존 PHYS68 인증서의 dyadic 사각형에서 저장된 D2까지 거리와 기준값의 크기를 다시 감쌌다. 방사 tail을 포함한 유리수 오차 기록 90개와 저장 complex 값의 정확한 분수 36개가 모두 원본 POINT_ERROR와 일치했다. 상대 오차 상계는 느슨한 그룹에서 GMRES 1.47278518e-10 / block 1.47285672e-10, 엄격한 그룹에서 GMRES 1.27170401e-12 / block 1.27015323e-12다. 이는 이 저장된 finite-L D2 값에 대한 인증이며 전 적분 알고리즘·각도 무한합·원래 source-driven xi 인증으로 확대하지 않는다.

Scalar/SIMD의 6개 대응 쌍에서 보존된 두 상태의 2,808개 성분을 IEEE-754 비트로 비교해 모두 일치했다. 각 엔진·허용오차 조합의 3회 반복도 상태가 비트까지 같다. 기존 GMRES와 block의 상태는 비트까지 같지 않다. 중간 궤적 전체의 상태는 이 영수증에 보존되지 않았다.

## 시간과 변동의 범위

위 표의 타이머는 `solve()` 앞에서 시작하므로 모델·워크스페이스 초기화와 적분을 포함한다. 타이머 종료 전 counter/진단 메타데이터의 반환용 변환도 포함한다. 프로세스 기동, 입력 읽기, endpoint 추출과 최종 JSON 출력은 제외된다. 프로세스 wall 중앙값으로 따로 계산하면 GMRES/SIMD는 각각 48.04배, 71.67배다. wall에는 subprocess 대기 방식의 부가 시간이 포함된다.

각 엔진의 표본은 3개이며 두 번째 표본의 실행 순서를 뒤집었다. rtol3e-10 SIMD 시간은 0.02982–0.06236 s로 변동했다. rtol3e-12 scalar도 0.11818–0.20123 s로 변동했다. 주장은 세 표본 중앙값의 비율에 한정한다. 대응 표본별 비율의 중앙값은 각각 98.6823배, 90.3460배이며 중앙값 비율과 구분한다. 이 수치는 현재 NCP 또는 L64의 예상 시간이나 다른 VigilODE 방법 전체의 성능 주장이 아니다.

같은 수락 단계 수에서도 GMRES의 JVP가 236,208 / 611,143회인 데 비해 block은 실제 shifted residual 확인을 위한 5,624 / 14,552회다. 각 단계에서 구조를 이용해 선형식을 직접 소거한 영향이 핵심이며, scalar→SIMD 추가 개선의 중앙값 비율은 1.45977배 / 1.32676배다.

## 마이크로벤치마크 해석

저장된 PHYS69 상태에서 수행한 콜백 및 한 단계 검사는 새 완주 적분이 아니다. 공통 한 단계의 endpoint 상대 차이는 1.7243e-16이다. 8번째 stage의 상대 차이는 **1.0**이고 기존 embedded norm은 0이다. 기존 선형식의 절대 잔차 하한은 작은 RHS에 대해 0 해를 허용할 수 있으며 block의 norm은 3.5135e-6이다. 원래 상태 허용오차로 나눈 stage 차이의 최댓값 1.1337e-4는 사전 gate0.005 이하다. 따라서 endpoint·가중 차이의 gate 통과를 주장하며 전 stage 비트 일치는 주장하지 않는다. 이 norm들은 전역 오차 경계가 아니다.

콜백 시간은 중앙값으로 기존 RHS/SIMD 1.919배, 기존 JVP/frozen JVP 2.585배다. 한 단계 12회 묶음의 중앙값 비율은 85.74배다. 마이크로 JSON에는 원시 RHS·stage 벡터가 없으므로, 해당 비트 일치 flag는 해시가 맞는 producer의 실제 assertion 결과로 분류했다. 이를 보존된 원시 벡터에서 이번에 재계산했다고 주장하지 않는다.

## 메모리·병렬화·별도 진척

동일한 driver 범위의 보존 vector capacity는 256,280→30,632 bytes (8.366배, 88.047% 감소)다. 새 kernel의 별도 테이블·행 52,736 bytes를 더하면 83,368 bytes다. 기존 driver 표는 기존 model 저장공간을 포함하지 않으므로 전체 RSS 감소율을 이 수치로 주장하지 않는다.

8개 독립 frozen callback job에서 1/2/4 worker 중앙값은 19.582 / 14.837 / 7.707 ms다. 풀과 워크스페이스 생성은 타이머 밖이고, 4 worker 비율은 2.541배다. 이 기록은 콜백 묶음의 병렬화 증거다. 완주 궤적의 병렬 throughput은 별도 `parallel_trajectories` 결과를 읽어야 판단한다.
