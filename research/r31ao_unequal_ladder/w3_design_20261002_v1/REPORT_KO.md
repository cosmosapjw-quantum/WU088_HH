# WU088_HH: endpoint 오차를 유지하며 W3 적분 구간 축소

이번에 완료한 한 단계는 **primitive 0의 하단·상단 endpoint 오차를 분리하고, 더 작은 상한을 실제 계산으로 인증하는 설계**다. 전체 내부 적분에 먼저 필요한 비용 병목을 다뤘다. 기존 W1 성공 계산은 재실행하지 않았다.

## 실제 결과

| 항목 | 이전 W3 기록 | 이번 선택 |
|---|---:|---:|
| 양쪽 변수의 적분 구간 | `[1/256, 2^192]` | `[1/512, 2^40]` |
| endpoint 상계 | 약 `5.083373928910032e-7` | 약 `7.197783310056944e-11` |
| 정밀도 | 128 bits | 128 bits |
| 범위 | primitive 0, 정규화 전 | 같은 primitive·같은 signed107 입력 |
| log2 최대 간격 3의 타일 수 | 균등 분할 4,489 | 기존 W1 경계 보존 289 |

새 오차 예산은 `2^-21`이며 이전 W3의 **실제 유리수 상계**보다 엄격하다. 처음 생각했던 `2^-20`은 이전 상계의 상단 이진 구간일 뿐이므로 실행 전에 배제했다. 수정 전 제안과 사유는 따로 보존했다. 최종 D의 허용오차를 새로 정하거나 완화한 것은 아니다.

새 selector와 기존 endpoint 엔진을 각각 한 번 실행했다. 각각 60회·55회의 majorant 함수 호출을 사용했고, 프로세스 관찰 시간은 약 0.265초·0.465초였다. 실제 native 내부 적분 호출은 0회다. 기존 host의 hard wall/CPU, 512MiB 주소공간, 자식 생성 금지와 부모 종료 시 SIGKILL 경계를 사용했다. 이번 계산은 NCP/OpenMPI 성능 측정이 아니다.

고정 후보 다섯 개의 상계는 다음과 같다. 소수는 표시용이며 선택과 검증은 정확한 유리수 비교다.

| 상한 T | 분리한 endpoint 상계 | `2^-21` 만족 |
|---|---:|---|
| `2^32` | `4.717062169212127e-6` | 아니오 |
| `2^40` | `7.197783310056944e-11` | 예, 첫 통과 후보 |
| `2^48` | `2.274760457539101e-15` | 예 |
| `2^56` | `1.176500595171672e-15` | 예 |
| `2^64` | `1.176483837056096e-15` | 예 |

`2^40`은 **시험한 후보 중 첫 통과 값**이다. 모든 실수·이진 상한에서의 최적값이라는 주장은 하지 않는다. `2^32`의 실패는 이 보수적 상계가 예산을 넘었다는 뜻이며, 실제 적분 오차가 반드시 예산을 넘는다는 증명은 아니다.

후속 작업에 사용할 보수적 endpoint 상계는 두 실제 출력 중 큰 값인

`210391441856025388187544847887702514929 / 2923003274661805836407369665432566039311865085952`

이다. 기존 엔진 출력이 selector보다 정확히 `12 / 2923003274661805836407369665432566039311865085952` 크다. 이는 단계별 upward rounding 순서가 다른 계산의 출력 차이다. 두 값의 대소가 같아야 한다는 검증 조건을 만들지 않고 `max`를 채택했다. 채택 상계는 기존 W3 상계보다 약 7,062.4배 작다.

## 바뀐 이론·구현

기존 Gaussian majorant에는 이미 큰 t에서의 추가 `t^-3/2` 감쇠가 들어 있었다. 누락된 감쇠를 새로 넣은 것이 아니다. 기존 positive mass bound를 이용하여

`B(l,T) <= B_lower(l) + sum_{p=2..10} A_p T^-p`, `A_p >= 0`

로 분리했다. 원래 disjoint complement의 inside mass를 whole mass로 상계하고, 모든 양의 곱·합을 128-bit relative dyadic grid에서 위쪽으로 반올림한다. Frozen107의 107개 signed coefficient·저장 순서·primitive parameter·원 endpoint engine·callback source를 해시로 고정했다. 자세한 증명은 `tail_bound/DERIVATION.md`와 독립 검토에 있다.

하단 cutoff를 한 octave 낮춘 `1/512`에서 계산된 하단 기여 상계는 약 `1.176483836800384e-15`다. 기존 `exp_neg_bounds`의 절대 128-bit 양자화 바닥도 포함한 결과이며 exp 함수의 상대 128-bit 정확도를 주장하지 않는다. 정밀도나 오차 허용치는 낮추지 않았다.

reciprocal-square-root 변수 변환도 검토했지만 이번 실행에는 도입하지 않았다. 단순 callback 래핑으로는 복소 구간 제약이 풀리지 않으며, 두 변수의 tail corner에는 sector 변환과 새 정규화 kernel 계약이 필요하다. 그 분석을 보존하고, 현재 엔진에서 증명·계산할 수 있는 cutoff 분리에 집중했다.

## 다음 내부 적분을 위한 구체적 설계

새 log2 축은 `[-9,-6,-4,-1,2,5,8,11,14,17,20,23,26,29,32,35,38,40]`이다. 축당 17구간, 총 289타일이며, Cartesian cell의 내부는 겹치지 않고 정확한 dyadic 경계로 새 직사각형을 덮는다. 기존 W1 16타일의 경계가 그대로 포함된다. 기하적으로 새로 필요한 타일은 273개다.

타일 수는 이전 균등 설계보다 약 93.56% 줄었다. **실제 실행시간 단축 배수는 아직 측정하지 않았다.** 타일 위치·난이도와 허용 radius에 따라 비용이 달라진다. 기존 W1 결과를 새 전역 plan에 재사용하려면 source/input/backend/window 동일성과 집계를 확인하는 명시적인 collector 계약이 필요하다. 현재 16타일 collector의 제한을 몰래 늘리지 않았다.

후속 내부 적분의 조건부 예산 설계는 새 타일당 radius `2^-57`, 기존 W1 실제 radius의 정확한 재사용이다. 모두 통과하면 `기존 W1 max radius + 273 * 2^-57 <= 2^-48`임을 유리수로 확인했다. 이는 기존 compact component 수준의 예산 설계이며 최종 정규화·contraction 후 D의 충분성을 뜻하지 않는다.

다음 우선 작업은 **새 collector의 구간·재사용 계약을 구현하고, 새 하단/상단 strip에서 작은 대표 pilot을 실행해 실제 수렴·비용을 확인하는 것**이다. 그 결과에 따라 273개 나머지 타일의 유한자원 실행 계획을 확정한다. 이전 W1 성공분은 재실행하지 않는다.

## 검증·보존 범위

selector의 정확 산술 합성 검증 9개와 DB builder의 합성 검증 17개가 통과했다. 독립 검토에서 발견된 worker의 `assert` 의존 검사는 실제 실행 전에 명시적인 실패 검사로 바꿨고, DB의 symlink namespace 우회도 회귀 검증과 함께 수정했다. 실행 기록·원본 stdout/stderr·source pins·계획·유리수 결과를 보존했다.

이전 W1 파일 197개의 SHA-256·크기·수정시간은 그대로다. 감사 DB는 원 DB의 SQL 객체와 행을 보존하며 새 실행 2회·후보 polynomial 평가 5회·native 적분 0회를 별도로 기록한다. DB 무결성·외래키·SQL dump 재복원 결과와 실제 게시·백업 ACK는 별도 delivery 기록을 기준으로 한다.

이 결과는 primitive 0의 endpoint 설계 완료다. 새 구간의 전체 내부 적분, 모든 2,592 primitive, 정규화와 contraction, 실제 Gram/model-gap, 최종 D/epsilon·판정은 아직 완료되지 않았다. G0–G9 전체 완료, scientific admission, production admission은 모두 false로 유지한다. 원 Deep Research DB의 출처 공백과 B22 완료 claim 잔존 원인 미확정도 그대로 열려 있다.
