## Concrete native driver contract

A coherent additive driver is possible using existing formulas. The safe first native vertical slice is **one indexed primitive's complete positive-domain enclosure**, followed by the same worker over the complete index set and the existing assembler. It requires real implementation and verification of the following interfaces; the current repository does not already provide them.

1. **Exact inputs and job identity.** Reuse `frozen_input.adapter.decode_npz(bytes, expected_archive_sha256=..., scope=...)` and `generate_cpp(record, source_archive_bytes=...)`. Pinned code generation re-decodes original bytes; a record self-hash is insufficient. The generated `load_frozen107_rational_record(AssemblyInputs&)` populates source fields and fixes z exactly to 3/4. Bind source/input/backend identities, `(active,field,orbital,ia,ib)`, method, precision/caps and cutoffs in each job. Neither a pin nor a scope string grants scientific authority.

2. **Endpoint companion in Python.** Obtain exactly the same a,b,mu,d1,d2 and donor terms as native `canonical_parameters`/`stored_donor_terms`; do not infer a new normalization. For each nonzero `(i,j,k,c)` compute `C_F=gaussian_field_majorant(a,b,d1,d2,k,angular,field,...)`, then `complement_bound(i,j,mu,a,b,l_t,T_t,l_u,T_u,C_F,...)`. The primitive error bound is the exact rational sum of `abs(c)*bound`. Record term coverage and the disjoint-complement convention. Cache identical exact subexpressions if desired, but do not screen terms. The endpoint function's return is a bound on an unnormalized primitive, not final D. Cutoff selection must have a declared finite attempt/cost cap.

3. **Native compact worker.** Call `canonical_parameters(inputs,ia,ib,active)` and `stored_donor_terms(inputs)`. Construct `Slice` with owned parameter/term/contract lifetimes; adapt using `petras::field_bivariate`. Set `Bivariate`'s holomorphy/uniform flags only under the source/domain theorem binding. Call `integrate_nested_2d(out,bivariate,l_t,T_t,l_u,T_u,plan,budget)`: **inner=t, outer=u**. Choose **dyadic cutoffs** for this wrapper because it requires finite exact real endpoint balls; arbitrary rational conversion at finite precision is not necessarily exact. All three nested precisions must agree with `Contract.precision`. Use one FLINT thread and an outer hard process resource guard. Accept only successful status and achieved returned radii; tolerance requests are not evidence.

4. **Combine exactly once.** Add the endpoint remainder to the compact-interior enclosure, preserving the interior ball radius already returned by Arb. A disk bound B may conservatively become component errors ±B; then any later rectangular→disk conversion must include the resulting square-corner factor. Do not call the resulting rectangular radius B, add the interior error twice, or add X0–X8. Serialize certified native real/imaginary endpoints as exact integer/rational data using a pinned backend API; ordinary decimal/binary64 conversion is not an acceptable bridge. Preserve exact native dumps and execution identities as evidence. The exact serializer itself still needs implementation and tests.

5. **Coverage and final assembly.** The complete set is `2 active * 3 fields * 3 orbitals * 12 ia * 12 ib = 2592`, indexed by `primitive_index`. Reject missing/duplicate/mixed-source/mixed-window records, failed statuses and reused unaccepted attempts before populating `RealDomainPrimitiveIntegrals`. That object requires the all-positive-domain, unnormalized integrals. Only then call `assemble_real_domain`; normalization, stored orbital coefficients, parity/reflection, phase and row conjugation are already implemented there. Export Dcol in 47×2 and Drow in 2×47 semantic order. No normalization or conjugation belongs in the endpoint/analytic callback stage.

6. **Downstream decision.** Feed these exact final rectangles to a bounded T5/G8 composition module alongside admitted exact raw and stored model matrices. Full numeric completion requires actual target disks, actual epsilon, represented gaps and the unchanged sufficient predicates. Keep real continuous-target certification, historical machine replay, independent review and physical/production admission separate.

## Domain and feasibility boundaries relevant to that driver

- `callback.cpp:58–66,80–82,103–109` proves positivity of the **computed entire ball** minus a positive margin; it does not inspect only midpoints. Conservative dependency inflation can cause refusal. The fixed default margin can also exclude otherwise valid tiny-t or small-sigma cases. A driver must bind a justified margin to its finite cutoffs and record refusals; merely increasing quadrature effort does not fix the domain contract.
- T1's full M evaluator is **not a prerequisite for the first Petras path** if the already mapped analytic Acb callback certifies every box it accepts. Petras can refuse unsuitable analytic trial boxes. In contrast, an explicit Cauchy-midpoint or product-Chebyshev fallback must implement M/derivative bounds. Do not set an M constant from a sampled maximum or an outer midpoint.
- `petras_host.cpp:87–89` checks only booleans and a nonempty proof-reference string. These are caller obligations, not machine-verified source/domain evidence. Lines 212–225 do preserve the complete outer box and check a full inner-path range for an analytic outer trial. This is materially stronger than midpoint-only nesting, but no runtime certificate has been produced.
- Native synthetic callback/Petras compilation, exact output serialization, analytic toy full-domain integration, endpoint accounting, and final source-assembly tests must precede an actual primitive pilot. Native success on those tests would establish implementation evidence, not actual HH feasibility. Fixed caps must return INCONCLUSIVE on exhaustion; T4 does not promise completion within them.
- N/executor/`core.py:83–89` explicitly admits only `SYNTHETIC_ONLY`; its collector authenticates opaque task bytes, not integrals. N/native_cache/`VERIFICATION.json` says native equality remains unverified, while N/mpi_fortran/`VERIFICATION.json` distinguishes the tested C process bridge from uncompiled/unexecuted Fortran/MPI. Parallel scaffolding does not close G4–G8. First production integration can run one guarded serial primitive without MPI or the optional cache.
