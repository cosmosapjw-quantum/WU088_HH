# 물리·수학 연구 루프

내장 운영 규약 **1.0.0**, 승인 설계 **v0.2 (2026-10-12)**를 적용하라. 호출 이름 `physmath-research-loop`를 유지하라.

## 진입과 필요한 읽기

1. 현재 요청, 승인 범위, 탐색/수렴, 연구 대상, 완료 기준과 재개 지점을 확인하라. 현재 대화와 확인 가능한 자료로 해결되는 내용은 바로 반영하라.
2. [공통 연구 정책](references/RESEARCH_POLICY.md)을 읽고 적용하라. 같은 버전의 정책을 이미 읽었으면 변경 부분만 확인하라.
3. 이론·문헌·증명에는 [이론 R1–R10](references/THEORY_LOOP.md), 구현·수치기법·테스트에는 [코딩 C1–C10](references/CODING_LOOP.md)을 읽어라. 두 루프에는 이론의 식·가정·근거·남은 의무를 코딩 계약으로 전달하라.
4. 근거 채택, 재개, 외부 인계에는 [근거·상태·인계 계약](references/EVIDENCE_AND_HANDOFF.md)을 읽어라. 기존 프로젝트의 유효한 기록 형식을 재사용하라.
5. 구버전 선택, 이전 단계 이관, 도구·실행자 선택에는 [런타임과 구버전 연결](references/RUNTIME_AND_LEGACY.md)을 읽어라. 기본 실행은 내장 규약으로 수행하라. 모델 이름이 불명확해도 실제 제공되는 기능으로 진행하라.

별도 ZIP 취득은 원본 재현이나 명시적 구버전 선택에 필요한 경우에 수행하라. 실제 읽기·실행·검증·저장 상태를 각각 보고하라.

## 항상 유지할 규칙

- **실제 산출물:** 정의 → 전제 → 유도 → 계산식 → 구현 → 검증 → 물리적 해석의 필요한 연결을 수행하라. 문헌·계획·집필 요청은 그 목적에 맞게 완결하라.
- **각 10단계:** 필요한 단계부터 재개하고 유지된 전제·입력의 근거를 재사용하라. watchdog·no-go·정책 교정을 관련 단계에 통합하라.
- **직접 서술:** 조건·범위·근거 상태를 정확히 쓰고 반복적인 부정적 단서는 제거하라. 열린 증명은 실제 lemma·추정·구성으로 진행하라. 교정에서 진리조건을 보존하라.
- **형식화의 기여:** 예상 기여와 구체적인 첫 연결로 탐색하라. watchdog 지적에 대상·관측 근거·영향·최소 교정을 갖추어라.
- **Strong no-go:** 새로운 성과 채택에는 공통 정책의 NG1–NG7을 모두 확인하라. 실제 오류·반례는 정확한 범위에서 즉시 보고하라.
- **정책 override:** 현재 지시와 승인 범위에서 근거가 분명한 최소 교정을 적용하고 이전 규칙·근거·대체·영향·결과를 남겨라. 사용자 고정 목표와 실제 권한은 출처에 따라 관리하라.
- **실패 분류:** 이론·수치·구현·환경·권한/정책·입력 의존성을 구별하고 원인에 맞게 수정하라. 새 진단이 있는 수정·재실행을 계속하라.
- **검증 종료:** 유지된 identity·전제의 근거를 재사용하고 변경된 의존성만 검증하라. 해결된 지적을 닫고 다음 연구를 수행하라.
- **요청 완결:** 작업 단위의 완료와 전체 요청의 완료를 구별하라. 체크포인트를 보존하며 승인된 다음 단위를 이어가라. 실제 입력·권한·실행 의존성이 막힌 지점은 정확한 상태와 최소 재개 행동으로 보고하라.

## 개인화와 실행

별도 지정이 없으면 metric signature `(-,+,+,+)`를 사용하고 `c, ħ, k_B`를 유지하라. 관련 convention, 차원·부호, 초기/경계조건, 근사 차수, closure, 유효범위·극한을 검토하라. 수렴 범위는 사용자 고정 내용을 따르고 탐색은 필요한 대안에 열어 두어라.

현재 호스트의 도구·병렬 agent 기능을 확인하라. 독립적인 유도·문헌·코드 작업을 분담하고 기준 식·입력·수용 기준을 공유하라. 모델 이름으로 실행 능력·성공을 추정하지 말라. 독립 검토에는 원자료와 문제를 제공하라.

`rei_bianchi`의 해당 지속 통합 대화에서 지정된 실행 분담을 적용할 때만 [REI 실행 정책](references/REI_EXECUTION_POLICY.md)과 [해당 기록](references/REI_EXECUTION_POLICY.json)을 읽어라. 과거 commit·이관 상태는 시점이 있는 기록으로 취급하고 현재 상태는 실제 자료에서 확인하라. 현재 유효한 지시를 반영하며 계산 권한은 각 프로젝트에서 확인하라.

## 선택적 상태 도구

기존 기록만으로 충분하면 그대로 사용하라. 기계가 읽는 새 기록이 필요하면 [워크플로 메타데이터](references/WORKFLOW.json)와 다음 도구를 사용하라.

- `python3 <skill_root>/scripts/run_record.py init --task research|coding|both --unit-id UNIT --output PATH`: 새 기록 생성.
- `python3 <skill_root>/scripts/run_record.py check PATH`: 필드·참조·완료 근거·상태 일관성 검사.
- `python3 <skill_root>/scripts/resolve_model.py --harness gpt56|gpt6-astra --task research|coding|both`: 명시적 구버전 선택.

구조 검사 결과는 구조 검사 근거로 기록하라. 과학적 타당성은 원전·유도·계산·실행과 해당 검토로 판정하라.
