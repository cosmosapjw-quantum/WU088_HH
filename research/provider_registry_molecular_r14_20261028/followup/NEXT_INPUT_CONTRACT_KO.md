# 다음 입력 계약 — 범위 메모만

**PROPOSAL_ONLY / NOT_ADOPTED_IN_R14 / NOT_STARTED.** 최신 사용자 지시대로 현재 진행 중이던 R14 종료 작업만 마친다. 이 메모는 다음 연구 노드나 루프를 시작하지 않으며 새 증명·계산·구현·과학 실행을 포함하지 않는다. 완료된 R14 primary/reference/CAS를 재실행하지 않는다.

## 1. 실제 입력이 도착하면 입력 결속을 우선

Actual HD reactive array 또는 named physical consumer가 새로 제공되면 해당 입력의 원본 bytes·SHA·출처·버전을 확인하고, 실제 state order/basis, density, clock/units, consumer repo·path·function·commit을 같은 입력으로 결속하는 범위를 먼저 정한다. K/pi/destruction, 전체 w box, 모든 시작시각, zero-mass residual 및 whole fine/coarse-domain forcing 전제를 만족하는지 별도 계약에 명시해야 한다.

일부 자료만 왔다면 받은 부분과 남은 필드를 구체적으로 기록한다. Conditional consumer, synthetic fixture, H2 proxy, 누락값을 actual HD physical binding으로 승격하지 않는다. Native v=UNSPECIFIED 및 MISSING_NOT_ZERO, TIQM/SQM 구별을 유지한다. 별도 적격 입력·심사 전에는 HH_R10=OFF, production=NOT_ISSUED, L4=false, central/physical delta=0이다.

## 2. 실제 입력이 없을 때 보관할 보수적 후보

후속 후보는 **각 rational source cell에서 비음수 Bernstein B3 coefficients를 명시적으로 공급하는 conditional piecewise-cubic forcing**이다. 이는 full nonnegative cubic cone을 이미 처리한다는 제안이 아니다.

R14의 rational source-vertex 처리와 quadratic-derivative root isolation을 다음 차수에 그대로 이식할 수 없다. 일반 cubic source의 stationary points에 대한 algebraic 처리가 필요할 수 있으며, zero/multiplicity와 유한 positive-coefficient certification도 별도 의무다. 이 문제를 숨기지 않기 위해 후보 입력을 명시적인 nonnegative coefficients로 제한한다.

향후 별도 착수 시에는 quartic residual의 whole-cell enclosure를 rational Bernstein subdivision으로 구성하는 방법을 검토할 수 있다. 유한 depth/work cap, 반환 enclosure gap의 의미, signed-d scalar integration, 독립 reference의 서로 다른 계산 경로를 먼저 계약해야 한다. Exact irrational maximum이나 기존 96-step root 계약의 자동 승계를 주장하지 않는다. 이 문서에서는 그 증명이나 구현을 수행하지 않았다.

## 3. 착수 전에 필요한 별도 계약

새 입력/정리/API 범위, 실패·거부 조건, source/state/clock identity, closed-cell 및 left-limit 규약, 원래 t0부터의 global R memory를 먼저 고정한다. Source/observation/base cell 수, block 수, subdivision 총작업량, rational bit limits, 양방향 반올림, reference precision/guard, 실행 횟수·CPU·wall·memory도 독립적으로 고정해야 한다.

**현재 새 primary/reference/CAS allowance = 0/0/0.** 구체적인 새 자원 상한은 아직 정하지 않았고 어떠한 실행도 예약하지 않았다. 과거 allowance를 늘리지 않으며 새 DAG node·채택 수 변화는 0이다. Global remaining/full historical CPU는 null을 유지한다.
